# 第 2 課：プラグインで実際に何ができるのか？

> **一言でいうと**：「CSV を検索できるツールをモデルに持たせる」から「インターフェース全体を QQ2006 風に着せ替える」、さらには「Android スマホで dsh を動かす」まで——**DSH の一部であれば、プラグインで変えられます**。この課では、エコシステムに実在する 275 個のプラグインをもとに、この仕組みの実際の境界線を描き出します。

## 1. まずは全体の規模から

2026 年 8 月時点で、`dsh-external` 組織には **275 個の収録済みプラグインリポジトリ** があります（このサイトのプラグインページがまさにその一覧です）。タグ別に見ると、特に多い方向は次のとおりです：

| 方向 | 数 |
|---|---|
| インターフェースの改造（`web-ui`） | 76 |
| モデル向けツール（`tool`） | 35 |
| スキル（`skill`） | 18 |
| セッションとメモリ（`session`） | 16 |
| 純粋に遊び（`fun`） | 15 |
| デスクトップ（`desktop`） | 10 |
| ワークフロー（`workflow`） | 8 |

ひとつの傾向がはっきり見えます：**インターフェース系のプラグインが圧倒的に多い**のです。DSH の Web インターフェース自体が数十個の UI プラグインを組み合わせてできているため、パーツを 1 つ足したり差し替えたりするコストが極めて低いからです。

以下では「何を変えたいか」で 7 つのカテゴリに分け、それぞれ**実在するリポジトリ**を紹介します。

---

## 2. 7 種類の改造と実例

### 2.1 モデルに新しい「手」を与える：ツール

素の状態のモデルにできるのは、ファイルの読み書き、コマンドの実行、Web 検索くらいです。そこにどんな新しい能力でも追加できます：

| プラグイン | モデルに与える能力 |
|---|---|
| `dsh-tool-csv` | 依存ゼロの RFC 4180 パーサーで CSV を解析・検索・集計 |
| `dsh-latex` | 文書を書いたらワンクリックで PDF コンパイル、エラー位置を構造化して特定、サイドパネルでプレビュー |
| `dsh-vision` | 任意の OpenAI 互換ビジョンモデルにブリッジする `view_image` ツール——モデルが「画像を見られる」ようになる |
| `dsh-mineru` | MineRU のドキュメント解析機能をモデルに公開 |
| `zotero-harvest` | 複数ソースでの文献検索（OpenAlex / arXiv / Crossref…）、ダウンロードと解析、ローカルの Zotero への取り込み |

**これが最も一般的で、最も取り組みやすいカテゴリです**——第 3 課で実際に 1 つ書いてみます。

### 2.2 目に見えるものを変える

DSH の Web インターフェースは数十個の `ui-*` プラグインをつなぎ合わせてできているので、何かを差し込むのは簡単です：

| プラグイン | 何を変えるか |
|---|---|
| `dsh-ui-whale` | タイトルバーにドット絵のクジラが住みつき、考え中は尾を振り、ターンが終わると潮を吹く |
| `dsh-web-panel` | 本物のターミナルを UI に埋め込む（xterm.js + node-pty） |
| `dsh-split-panes` | 分割 / スタック表示のパネル、パネルごとに独立したセッション |
| `dsh-custom-css` | CSS を貼り付けるだけで即座に見た目を変更、設定に保存されブラウザ間で同期 |
| `dsh-genui` | モデルが会話の中にインタラクティブな UI を直接描く（グラフ、フォーム、クイズ、3D） |

### 2.3 モデルの考え方と協働の仕方を変える

単に「モデルを入れ替える」のではなく、モデルの働き**方**そのものを変えます：

| プラグイン | 何を変えるか |
|---|---|
| `dsh-plan-execute` | 計画段階では推論モデルを使い、承認後は自動的に高速モデルに切り替えて実行 |
| `dsh-advisor` | サブモデルが毎ターンを受動的にレビューし、気づきを注入する |
| `dsh-deep-research` | 適応型のディープリサーチのオーケストレーション |
| `dsh-llm-fallbacks` | ロール別のリトライとフォールバックモデルのポリシー |

### 2.4 メモリとセッションを変える

| プラグイン | 何を変えるか |
|---|---|
| `dsh-memory-evolve` | 階層型メモリ（ユーザー / プロジェクト / 日次）に加え、経験を新しいスキルへと蒸留 |
| `dsh-session-search` | ツールをまたいだ全文検索（dsh / codex / claude / pi / opencode） |
| `dsh-turn-rewind` | 会話**とワークスペース**を巻き戻す。永続的な変更台帳で駆動 |
| `dsh-sidechain` | `/side` で一時的なフォークにサイド会話を開き、メインスレッドを汚さない |

### 2.5 別の場所で使う

DSH はターミナルの中だけに住む必要はありません：

| プラグイン | どこへ行くか |
|---|---|
| `tg-bot` / `qqbot` / `dsh-feishu-bot` / `dsh-wecom-bot` | Telegram / QQ / Feishu / WeCom のボットになる |
| `dsh-vscode` | VS Code のチャットにネイティブ統合 |
| `dsh-browser` | ブラウザを直接操作する Chrome サイドパネル拡張 |
| `dsh-android` | Android スマホで動く |
| `dsh-desktop-electron` | トレイに常駐するクロスプラットフォームのデスクトップシェル |

### 2.6 純粋に遊びのため

ここに 15 個ものリポジトリがあること自体、ハードルの低さを物語っています：

| プラグイン | 何をするか |
|---|---|
| `dsh-pet` | DSH を閉じていてもセッションの状態を感知し、効果音で知らせるデスクトップのクジラ |
| `7d7d` | レトロなミニゲームポータル。モデルが生成したゲームを UI 上でそのまま遊べる |
| `dsh-gomoku` | AI と五目並べ、あるいは AI 同士で対局させる |
| `dsh-lazyfish` | 右側の「サボり」パネル：フィードと bilibili プレーヤー |
| `dsh-qq2006` | QQ2006 のフルスキン |

### 2.7 下層の部品を取り替える

このカテゴリは「カーネルが存在しない」ことを最もよく示しています——実行基盤そのものを差し替えるのです：

- **コマンド実行バックエンド**を差し替える（ローカル / サンドボックス / PowerShell / リモートサンドボックス）
- **セッションストレージ**を差し替える（JSONL / SQLite / リレーショナルデータベース）
- **サンドボックス実装**を差し替える（bwrap / Landlock / Seatbelt / microsandbox）
- **サブエージェントのドライバー**を差し替える（インプロセス / ACP / Codex / Claude Code）

これらは公式リポジトリに同梱されており、設定を 1 行変えるだけで切り替えられます。

## 3. では、*できない*ことは？

能力を宣伝するより、境界をはっきりさせるほうが役に立ちます。

**① プラグインは「物理法則」を変えられない。** プロトコル定数、外部 API の仕様、セキュリティ上の不変条件は固定です——サンドボックスに拒否されたファイル操作を「すり抜けさせる」ことはできません。拒否はポリシーの結果であって、バグではありません。

**② 一部の能力は設計上オプトイン。** 最もわかりやすい例が、自己言及的なツールセット `tool-cordis` です。これはモデルが実行中に自分自身へ新しいプラグインをマウントできるようにするもので、公式の立場は明確です：

> このツールセットは明示的な有効化が必要であり、bash ツールを与えるのと同じ慎重さで判断すべきです。

理由は率直です：モデルが書いたプラグインコードは、あなたが実行中のプロセスに本当に入り込みます。デフォルトで同梱しないのは正しい判断です。

**③ プラグイン同士は完全には隔離されていない。** 同じスロットを奪い合う 2 つのプラグインは衝突します——たとえば、どちらも唯一のセッションタイトル生成器になろうとする場合です。DSH の答えは、後から来たほうを黙って勝たせるのではなく、**ロード時に大きな声で失敗させる**ことです。これが「設定ミスは騒がしく失敗する」という原則であり、これは機能です：早く失敗するほうが、実行の途中でおかしな振る舞いをするよりずっと良いのです。

**④ すべてがプラグインにする価値があるわけではない。** 公式には「自前で実装するより、メンテナンスされている依存を優先する」というルールがあります——成熟したライブラリが、本来なら自分で抱えるはずのコードとテストを本当に削れる場合には、ライブラリを使うべきです。

## 4. 探し方とインストール

**探す**：

- このサイトの[プラグインページ](/plugins)——275 個のリポジトリをカテゴリで絞り込める
- `dsh-hub` / `dsh-plus`——コミュニティが厳選したリスト
- `marisa`（別名 dshx）——GitHub topic で自動発見する外部プラグインマネージャー

**インストールする**：たいていのプラグインの README にはワンライナーが載っています。公式の方法は profile に追加することです：

```sh
dsh plugin --profile web add <package or local path>
```

インストールすると `cordis.yml` にそのエントリが現れます。外したくなったらその行を削除するだけ——**第 1 課のルールに戻りましょう：入れられるものは、外せる。**

> 💡 実用的なアドバイス：まずは「モデルにツールを与える」系のプラグインから始めましょう（たとえば `dsh-toolkit` に含まれる依存ゼロの 6 つのユーティリティ）。UI にも基盤にも触れないので、問題が起きても影響範囲が最小で済みます。

## 要点の振り返り

1. **275 個の実在プラグイン**。特に多いのはインターフェースの改造（76）、モデル向けツール（35）、スキル（18）。
2. **7 つの改造方向**：ツールを追加する、UI を変える、モデルの協働の仕方を変える、メモリとセッションを変える、動く場所を変える、純粋に遊ぶ、基盤の部品を取り替える。
3. **インターフェース系が最多**なのは、Web UI 自体が数十個の UI プラグインでできており、追加の限界コストが極めて小さいから。
4. **境界は実在する**：プロトコルとセキュリティの不変条件は固定、自己言及的ツールセットはデフォルトでオフ、衝突はロード時に失敗する。
5. **インストールもアンインストールも設定の変更にすぎない**——`cordis.yml` の該当行を消せば元どおり。
